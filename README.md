# Генератор сопроводительных писем для IT-вакансий

Локальный веб-приложение на Flask, которое собирает сопроводительное письмо
для отклика на вакансию по тексту резюме и тексту вакансии.

Анализ текста — **только правиловый, на чистом Python**. Внешние AI-сервисы,
API, базы данных и CDN не используются вообще. Текст резюме никуда не
отправляется и не сохраняется: письмо собирается в памяти и отдаётся обратно
в браузер.

```
Резюме + Вакансия  ->  analyze_resume / analyze_vacancy  ->  match_skills
                   ->  сборка абзацев по шаблонам направления  ->  письмо
```

## Возможности

- 4 направления: **Backend Developer**, **Web/Frontend Developer**,
  **Manual QA**, **Automation QA** (расширяется добавлением файла).
- Локальный анализатор резюме: имя, должность, стаж, компании, технологии,
  soft skills, образование.
- Локальный анализатор вакансии: название, обязательные и желательные
  требования, опыт, обязанности, требования, компания (если она названа).
- Сопоставление навыков на три списка: `MATCHED` / `MISSING` / `OPTIONAL`.
- 3 стиля письма: **Профессиональный**, **Краткий** (до 1000 символов,
  цель — 700–1000), **Уверенный**.
- Панель «Что найдено в вакансии» с тегами совпадений, пробелов и
  желательных требований.
- Письмо сразу редактируется в textarea, оттуда его можно
  **скопировать** или **скачать .txt**.
- **Контент для VK** (необязательно): 3 типа поста на основе уже разобранной
  вакансии — разбор, проверка навыков и совет соискателю. Пост можно
  отредактировать, скопировать и **опубликовать в группе** — только после
  явного подтверждения. Настраивается через `.env`, см. раздел
  «Публикация в VK».

### Главное обещание: письмо не врёт

Навык, которого нет в резюме, **никогда** не попадает в письмо — даже если он
есть в вакансии. Это обеспечено тремя независимыми механизмами:

1. **Шаблоны рендерят только подтверждённые факты.** Подстановка работает
   только по данным, найденным в резюме. Если подставлять нечего, блок целиком
   выбрасывается, а не «додумывается».
2. **Цитаты из вакансии фильтруются.** Задача из вакансии вставляется в письмо
   в кавычках только если все её упомянутые навыки есть в резюме.
3. **Финальная проверка `verify_cover_letter()`.** Готовый текст сверяется с
   исходными текстами резюме и вакансии; всё, чего там нет, удаляется.
   Кавычки `«…»` трактуются как цитата: внутри должен быть дословный
   фрагмент исходного текста.

Ключевой тест-пример (`tests/test_generator.py`):

```python
# В резюме: Python, Django, PostgreSQL
# В вакансии: Python, Django, PostgreSQL, Docker
result = generate_cover_letter(resume_text=..., vacancy_text=...)
assert result.matched_skills == ["Python", "Django", "PostgreSQL", "SQL"]
assert result.missing_skills == ["Docker", "Linux"]
assert "Docker" not in result.cover_letter
```

## Требования

- **Python 3.11 или новее** (проверено на 3.12)
- **Flask** — единственная зависимость

Фреймворков на клиенте нет: только HTML5, CSS3 и Vanilla JavaScript.

## Установка

```bash
# 1. Виртуальное окружение
python -m venv .venv

# 2. Активация
# Windows (PowerShell):
.venv\Scripts\Activate.ps1
# Windows (cmd):
.venv\Scripts\activate.bat
# macOS / Linux:
source .venv/bin/activate

# 3. Зависимости
pip install -r requirements.txt
```

## Запуск

```bash
python app.py
```

Открыть <http://127.0.0.1:5000>.

Сервер поднимается только на `127.0.0.1`, в интернет не выходит. Порт можно
поменять переменными окружения:

```bash
# Windows (PowerShell)
$env:PORT=5050; python app.py
# macOS / Linux
PORT=5050 python app.py
```

Остановка — `Ctrl+C`.

## HTTP API

### `POST /generate`

Запрос:

```json
{
  "resume": "текст резюме",
  "vacancy": "текст вакансии",
  "profession": "backend",
  "style": "professional"
}
```

Успех — `200`:

```json
{
  "success": true,
  "cover_letter": "Здравствуйте! ...",
  "matched_skills": ["Python", "Django", "PostgreSQL", "SQL"],
  "missing_skills": ["Docker", "Linux"],
  "optional_skills": ["Kubernetes", "Redis"],
  "resume_only_skills": ["Celery"],
  "warnings": [],
  "profession": "backend",
  "style": "professional",
  "detected_profession": "backend",
  "vacancy_company": "Финтех",
  "vacancy_title": "Backend Developer"
}
```

Ошибка — `400` с понятным текстом:

```json
{ "success": false, "error": "Добавьте текст резюме.", "field": "resume" }
```

Поля ответа:

| Поле | Смысл |
|------|-------|
| `cover_letter` | готовый текст письма |
| `matched_skills` | навыки, которые есть и в резюме, и в требованиях вакансии |
| `missing_skills` | обязательные требования, которых в резюме нет |
| `optional_skills` | желательные требования, которых в резюме нет |
| `resume_only_skills` | навыки из резюме, которых нет в вакансии |
| `warnings` | предупреждения, например слишком короткий текст |
| `profession` | направление, по которому реально собрано письмо |
| `detected_profession` | направление, определённое по тексту |
| `vacancy_company` | компания из вакансии, если она названа |
| `vacancy_title` | должность из вакансии |

### `GET /api/meta`

Справочник направлений, стилей и типов постов VK. В ответе есть объект
`vk` со статусом интеграции (`enabled`) и лимитами. Ключа доступа в нём
нет и быть не должно.

### `POST /vk/post`

Собирает текст поста для предпросмотра. **Ничего не публикует.**

```json
{"resume": "...", "vacancy": "...", "post_type": "vacancy_breakdown"}
```

| `post_type` | Что делает |
|-------------|------------|
| `vacancy_breakdown` | Разбор вакансии: требования, совпадения с резюме, пробелы |
| `skill_check` | Проверка, что генератор не приписывает отсутствующие навыки |
| `career_advice` | Совет соискателю; работает без резюме и вакансии |

Ответ: `{"success": true, "post_type": "...", "text": "...", "chars": 379, "max_chars": 4000, "warnings": [...], "site_url": "..."}`.

### `POST /vk/publish`

Публикует **отредактированный** текст из предпросмотра на стене группы.
Вызывается только после явного подтверждения пользователем.

```json
{"text": "..."}
```

Ответ: `{"success": true, "post_id": 17, "url": "https://vk.com/wall-123_17"}`.
Ошибки: `400` — текст не годится или VK не настроен, `502` — VK отклонил
запрос. В ответе нет traceback и нет ключа доступа.

### `GET /`

Страница приложения.

## Как это расширять

### Добавить навык

Всё в одном файле — `generator/skills.py`. Найдите нужную секцию и допишите
одну строку:

```python
Skill("Airflow", ("airflow", "apache airflow"), CATEGORY_INFRA),
```

Формат: `Skill(имя, (алиасы...), категория)`. Имя увидит пользователь, по
алиасам идёт поиск в тексте.

Специальные случаи:

- `context_only=True` — навык распознаётся только рядом со списком навыков.
  Так короткие слова вроде `Go` и `C` не дают ложных срабатываний.
- Алиас, оканчивающийся на `*`, работает как префикс: `("регресси*",)`.
- Если навык подразумевает другие, добавьте их в `IMPLIES`:
  ```python
  IMPLIES = {..., "PostgreSQL": ("SQL",)}
  ```

### Добавить профессию

Создайте файл рядом с существующими в `generator/professions/`, например
`data_analyst.py`. Он подгрузится автоматически — реестр сканирует папку,
правки в других файлах не нужны.

Нужен объект `PROFESSION` и функция `build_paragraphs`:

```python
from ..skills import CATEGORY_DATABASE, CATEGORY_LANGUAGE, CATEGORY_TOOL
from .base import (
    Profession, closing, experience_line, greeting, interest_line, skill_line,
)

PROFESSION = Profession(
    id="data_analyst",
    label="Data Analyst",
    short_label="Data",
    description="Аналитика данных, SQL-отчёты, визуализация.",
    default_title="Data Analyst",
    focus_genitive="аналитики данных",
    focus_dative="аналитике данных",
    focus_prepositional="аналитике данных",
    detection_keywords=("analyst", "аналитик", "data", "sql", "bi"),
    # Порядок важен: категории, которые стоят раньше, попадают в письмо
    # первыми, когда навыков много, а места хватает не на все.
    focus_categories=(CATEGORY_LANGUAGE, CATEGORY_DATABASE, CATEGORY_TOOL),
)

_INTEREST = ("Откликаюсь на вакансию {title}.",)
_EXPERIENCE = ("В аналитике данных работаю {years}.",)
_STACK = ("Основной стек: {skills}.",)


def build_paragraphs(ctx):
    return [
        greeting(ctx),
        interest_line(ctx, _INTEREST, "data-interest"),
        experience_line(ctx, _EXPERIENCE, "data-experience"),
        skill_line(ctx, _STACK, "data-stack"),
        closing(ctx),
    ]
```

Чтобы карточка шла в нужном месте, впишите `id` в `PROFESSION_ORDER`
в `generator/professions/__init__.py`; новые направления и так добавляются в
конец автоматически.

### Изменить формулировки

Формулировки лежат в каждом модуле направления как кортежи строк — это пулы
вариантов. Хотите изменить тон или добавить вариант: правьте нужный пул,
например `_STACK` в `generator/professions/backend.py`.

Каждая строка-вариант может содержать подстановки вида `{skills}`, `{years}`,
`{company}`. Если подставлять нечего, строка просто не используется.

Если вариантов несколько, выбор **детерминированный**: он считается через
SHA-256 от «зерна» (направление + стиль + хеши обоих текстов) и номера слота.
Один и тот же вход всегда даёт один и тот же результат, а разный вход —
разные формулировки. Зерно можно задать вручную:

```python
from generator import generate_cover_letter

generate_cover_letter(resume_text=..., vacancy_text=..., seed="42")
```

### Добавить стиль письма

Всё в `generator/styles.py`, добавить запись в `STYLES`:

```python
"formal": StyleSpec(
    id="formal",
    label="Официальный",
    description="Максимально сдержанный тон.",
    max_skills=5,
    include_soft_skills_block=False,
),
```

Задают длину и состав письма: сколько навыков упоминать (`max_skills`),
какие блоки включать (`include_*_block`), тон (`enthusiasm`) и ограничение
длины (`brief`). Карточка стиля в интерфейсе появится сама.

## Ограничения и настройка

Все пороги собраны в `generator/config.py`:

| Параметр | Значение | Зачем |
|----------|----------|-------|
| `MIN_INPUT_CHARS` | 10 | короче — считается пустым вводом |
| `MIN_MEANINGFUL_WORDS` | 3 | отсекает случайные слова вместо резюме |
| `RECOMMENDED_INPUT_CHARS` | 200 | ниже порога показывается подсказка |
| `MAX_INPUT_CHARS` | 20000 | защита от слишком больших текстов |
| `BRIEF_MIN_CHARS` / `BRIEF_MAX_CHARS` | 700 / 1000 | границы стиля «Краткий» |
| `MAX_SKILLS_MENTIONED` | 7 | максимум навыков в одном письме |
| `MAX_TASKS_QUOTED` | 2 | максимум цитируемых задач из вакансии |
| `BANNED_PHRASES` | — | формулировки, которые запрещено использовать |

### Про нижнюю границу «Короткого» письма

`BRIEF_MIN_CHARS` — это **цель, а не гарантия**. Если письмо получилось короче
700 символов, генератор сначала попробует достать из резюме то, что ещё не
использовал:

1. поднять лимит навыков, чтобы показать больше совпадений с вакансией
   (это подтверждённые факты, а не выдумка);
2. добавить неиспользованные навыки резюме;
3. процитировать ещё одну задачу из вакансии;
4. добавить стаж с компанией;
5. добавить soft skills и образование — то, чего стиль по умолчанию не
   показывает.

Если в резюме больше нечего добавить, письмо останется коротким, а в поле
`warnings` появится сообщение:

> Данных в резюме немного, поэтому письмо получилось короче 700 символов.

Добивать длину выдуманными формулировками нельзя — это сломало бы главное
обещание генератора, поэтому короткое письмо лучше, чем правдивое, но длинное.
Предупреждение о длине честное: оно означает «в резюме нечего добавить», а не
«мы придержались красивого лимита».

Что стиль «Краткий» по умолчанию **не** включает: блок `soft skills` — это
общие слова, в коротком письме они только занимают место. Образование —
факт, поэтому оно включается. Управляется флагами `include_*_block` в
`generator/styles.py`.

Про письма сказано: никаких «я лучший кандидат» и «идеально подхожу» —
такие фразы отсекаются, а формулировки пишутся нейтрально, без указания
рода (`готов` не используется вообще). Это проверяется тестом по исходникам
шаблонов, а не только по готовым письмам.

## Гарантии приватности

- Текст резюме и вакансии **не сохраняется**: ни в базе, ни в файлы, ни в
  `localStorage`/`sessionStorage`/куках.
- Логирование Werkzeug отключено, чтобы содержимое запроса нигде не
  всплыло.
- Все ответы помечены `Cache-Control: no-store`.
- Ни одного обращения во внешнюю сеть: ни CDN, ни шрифтов, ни аналитики.
  CSS, JS, иконка и favicon лежат в `static/`. Единственное исключение —
  публикация в VK, и только по вашему явному нажатию, см. раздел
  «Публикация в VK».
- Сервер слушает только `127.0.0.1`.
- В посты VK персональные данные не попадают: имя, телефон, почта и личные
  ссылки вырезаются, а перед публикацией текст проверяется ещё раз.

# Публикация в VK

По желанию приложение умеет готовить пост для группы ВКонтакте и
публиковать его на стене сообщества. Функция **необязательная**: без
настроек всё работает как раньше, посты создаются и копируются, а кнопка
публикации объясняет, что не так.

Ключевая гарантия та же, что и у писем: **навык, которого нет в резюме,
никогда не преподносится как опыт кандидата**. В посте он может
упоминаться только там, где прямо сказано, что в резюме его нет.

## Как это работает

```
разбор вакансии (generator.analyze_pair)
        ↓ уже готовые факты, без повторного анализа
генератор поста (vk.post_generator)
        ↓ текст + проверка правдивости и приватности
клиент VK (vk.api)  ──HTTP──▶  стена сообщества
        ↑
Flask-маршрут (app.py) → vk.service
```

Вакансия разбирается **один раз**: и письмо, и пост получают одни и те же
факты и одно и то же сопоставление навыков.

## Настройка

### 1. Получите ключ доступа сообщества

Нужен именно **токен сообщества** с правом на записи (`wall`).

- **Простой способ.** Откройте сообщество → Управление → Настройки →
  Работа с API → Создать ключ. Включите право **«Записи»** и, если
  планируете прикреплять файлы, «Загрузка файлов». Скопируйте ключ —
  он показывается один раз. Создать его может только администратор.
- **OAuth.** Если сервер не привязан к одному IP, подойдёт
  [Authorization Code Flow](https://id.vk.ru/about/business/go/docs/ru/vkid/latest/oauth/oauth-vkontakte/authcode-flow-community):
  запросите `scope=groups`, возьмите id сообщества методом `groups.get`
  с `filter=admin` и обменяйте `code` на токен через
  `https://oauth.vk.com/access_token`. Такой токен не ограничен одним IP.

Полезно знать: у ключа сообщества **нет срока действия**, но его можно
отозвать в любой момент в тех же настройках.

### 2. Заполните `.env`

Скопируйте `.env.example` в `.env` в корне проекта:

```bash
cp .env.example .env      # macOS / Linux
copy .env.example .env    # Windows (PowerShell)
```

```dotenv
VK_GROUP_ID=123456
VK_ACCESS_TOKEN=ваш_ключ_сообщества
VK_API_VERSION=5.199
SITE_URL=https://ваш-сайт.example
```

| Переменная | Обязательна | Значение |
|------------|-------------|----------|
| `VK_GROUP_ID` | для публикации | id сообщества цифрами. Принимаются `123456`, `-123456`, `https://vk.com/club123456` |
| `VK_ACCESS_TOKEN` | для публикации | ключ доступа сообщества с правом на записи |
| `VK_API_VERSION` | нет | версия API, по умолчанию `5.199` |
| `SITE_URL` | нет | адрес, который ставится в конец поста. По умолчанию `http://localhost:5000` |

Необязательно: `VK_TIMEOUT` (таймаут запроса, по умолчанию 10 секунд),
`VK_MAX_REQUIREMENTS` (6), `VK_MAX_MATCHES` (5), `VK_MAX_MISSING` (5),
`VK_MAX_POST_CHARS` (4000).

Файл `.env` уже добавлен в `.gitignore` — в репозиторий он не попадёт.
Значение из окружения имеет приоритет над файлом, поэтому на сервере
секреты удобнее задавать именно окружением.

### 3. Запустите приложение

```bash
python app.py
```

Больше ничего настраивать не нужно. Перезапускать после правки `.env`
не требуется: настройки читаются при каждом запросе.

## Как пользоваться

1. **Создайте сопроводительное письмо** как обычно — вставьте резюме и
   вакансию, нажмите «Создать сопроводительное письмо».
2. Ниже появится блок **«Контент для VK»**. Выберите тип публикации:
   - **Разбор вакансии** — что ищут, что совпадает с резюме, чего не хватает;
   - **Проверка навыков** — пост о том, что генератор не приписывает лишнего;
   - **Совет соискателю** — короткий пост, работает даже без резюме и вакансии.
3. Нажмите **«Создать пост для VK»**. Текст появится в предпросмотре, рядом
   будет счётчик символов. Генерация ничего не публикует.
4. **Отредактируйте текст** в поле предпросмотра — так вы решаете, что
   именно уйдёт в группу.
5. Нажмите **«Копировать»**, чтобы забрать текст без публикации, или
   **«Опубликовать в VK»**.
6. Появится диалог: **«Опубликовать этот пост в группу VK?»** с кнопками
   **«Опубликовать»** и **«Отмена»**. `Esc` и щелчок по фону — тоже отмена.
   Публикации без вашего нажатия в этом диалоге не бывает.
7. После публикации появится номер записи и ссылка на неё.

## Что попадает в пост, а что нет

В посте **нет** и не может появиться:

- полного текста резюме;
- имени кандидата;
- телефона и адреса электронной почты;
- ссылок на личные аккаунты — единственная разрешённая ссылка это `SITE_URL`.

Как это обеспечено:

- в пост идут только навыки из разбора вакансии и название должности;
- должность из вакансии дополнительно очищается от почты, телефонов и ссылок,
  потому что это пользовательский ввод;
- перед отправкой на стену тот текст, который вы видите, проверяется ещё раз:
  пустой или слишком длинный, с почтой, телефоном или чужой ссылкой —
  публикация не состоится, а вы увидите, что именно убрать;
- проверка правдивости навыков живёт в `vk/post_generator.py`: каждый блок
  текста помечен ролью, и навык без опыта в резюме допускается только в
  блоках «требования вакансии» и «пробелы». Если шаблон когда-нибудь нарушит
  это правило, пост просто не соберётся.

## Как отключить VK

Ничего не нужно удалять. Опустошите или удалите `.env` — и интеграция
выключится. Приложение продолжит работать: письма, анализ и создание
постов останутся доступны, а публикация ответит «VK API не настроен.» и
подскажет, каких переменных не хватает. Никаких падений и traceback.

## Безопасность ключа доступа

Ключ доступа — самый чувствительный элемент проекта. Он используется
**только сервером** и не покидает его:

- не попадает в HTML и не отдаётся в JavaScript — в браузер уходит только
  факт «настроено / не настроено»;
- не попадает в URL запроса к VK: передаётся в заголовке
  `Authorization: Bearer …`, поэтому не всплывает в логах и истории;
- не попадает в логи: логирование Werkzeug отключено;
- не попадает в сообщения об ошибках: коды VK переводятся в понятные фразы,
  сырой `error_msg` пользователю не показывается;
- `repr` настроек замаскирован (`access_token=***`), поэтому токен не утечёт
  даже через случайный `print(settings)` в отладке;
- не коммитится: `.env` в `.gitignore`, а в репозитории лежит только
  `.env.example` с пустыми значениями.

Запрос уходит только на `api.vk.ru`: если ответ пришёл с другого домена
(например, после редиректа), публикация отменяется — так заголовок с
токеном не уедет на сторонний сервер.

Если ключ скомпрометирован, отзовите его в настройках сообщества и создайте
новый. История публикаций не ведётся, восстановить ничего не нужно.

## Технические детали

- Метод: [`wall.post`](https://dev.vk.com/ru/method/wall.post), версия
  `5.199`, адрес `https://api.vk.ru/method/wall.post`.
- Параметры: `owner_id` со знаком минус, `message`, `from_group=1`, `v`.
- Ответ об успехе: `{"response": {"post_id": 17}}`; об ошибке:
  `{"error": {"error_code": 214, "error_msg": "..."}}`.
- Права токена: сообщества с правом на записи. `wall` для пользовательского
  токена VK выдаёт по обращению в поддержку, поэтому для серверной публикации
  нужен именно токен сообщества.
- Зависимостей не добавилось: HTTP-запрос делает `urllib` из стандартной
  библиотеки, разбор `.env` — тоже свой, ~20 строк в `vk/config.py`.

## Использование как библиотека

Пакет `generator` работает и без веба:

```python
from generator import generate_cover_letter

result = generate_cover_letter(
    resume_text="Резюме: Python, Django, PostgreSQL, 3 года опыта.",
    vacancy_text="Вакансия: Python, Django, PostgreSQL, Docker.",
    profession="backend",
    style="professional",
)

print(result.cover_letter)
print(result.matched_skills)   # ['Python', 'Django', 'PostgreSQL', 'SQL']
print(result.missing_skills)   # ['Docker', 'Linux']
```

Пакет `vk` тоже работает без веба. Сборка поста безопасна: публикации
в ней нет, а HTTP-запрос можно подменить:

```python
from generator import analyze_pair
from vk import VkClient, VkSettings, generate_vk_post

# Анализ делается один раз и переиспользуется письмом и постом.
analysis = analyze_pair(
    "Резюме: Python, Django, PostgreSQL, 3 года опыта.",
    "Вакансия: Python, Django, PostgreSQL, Docker.",
)

settings = VkSettings(group_id="123456", access_token="...", site_url="https://site.example")
post = generate_vk_post(analysis, "vacancy_breakdown", settings.site_url, settings.limits)
print(post.text)

# Публикация с подменённым транспортом вместо сети:
client = VkClient(settings, opener=lambda request, timeout: {"response": {"post_id": 17}})
print(client.publish_post(post.text).url)   # https://vk.com/wall-123456_17
```
